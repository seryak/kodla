# Справочник CLI-команд

В руководстве собраны команды бинарника `kodla` и внешней утилиты `tasar`.
Slash-команды AI-навыков намеренно не включены: это другой интерфейс, работающий в AI-редакторе.

## Быстрый старт

Установите пакет глобально или скачайте бинарник, как описано в [README](../README.md#установка), затем проверьте доступность команд:

```bash
kodla list
tasar --help
```

Команды выполняются из корня целевого проекта: некоторые из них создают или изменяют файлы относительно текущей директории.

## Команды Kodla

Текущая версия бинарника регистрирует три прикладные команды.

| Команда | Назначение |
|---|---|
| `kodla init` | Показывает доступные AI-навыки Kodla. |
| `kodla plan-init <name>` | Создаёт заготовку плана в `.kodla/plans/`. |
| `kodla config-update --target <config> --payload <json>` | Обновляет конфигурацию, сохраняя комментарии. |

### `kodla init`

Выводит список установленных навыков и подсказывает, как начать настройку AI-контекста.

```bash
kodla init
```

Команда не принимает аргументов и не создаёт файлы проекта.

### `kodla plan-init <name>`

Создаёт файл `.kodla/plans/<name>.md` с разделами для настроек, задач и плана коммитов. Имя плана должно быть стабильным идентификатором в kebab-case.

```bash
kodla plan-init add-notifications
```

Если каталог `.kodla/plans/` отсутствует, он будет создан. При существующем файле команда не перезаписывает его.

### `kodla config-update --target <config> --payload <json>`

Обновляет YAML-конфигурацию из JSON-payload, используя шаблон Kodla. Оба параметра обязательны.

```bash
kodla config-update \
  --target .kodla/config.yaml \
  --payload /tmp/kodla-config.json
```

| Параметр | Обязателен | Значение |
|---|---:|---|
| `--target` | Да | Путь к обновляемому `config.yaml`. |
| `--payload` | Да | Путь к JSON-файлу с изменениями. |

Это служебная команда для автоматизации. Не редактируйте `.kodla/config.yaml` через неё с непроверенным JSON: некорректные данные приведут к ошибке обновления.

## Внешняя CLI Tasar

Tasar — отдельная утилита управления изменениями. Она не регистрируется бинарником `kodla`, но используется совместно с ним для жизненного цикла спецификаций: создание изменения → работа над ним → синхронизация и архивирование.

Ниже приведены команды, принятые в интеграции Kodla. За точными доступными флагами установленной версии обращайтесь к `tasar --help`.

| Команда | Назначение |
|---|---|
| `tasar init` | Инициализировать структуру Tasar в проекте. |
| `tasar new <name>` | Создать новое изменение. |
| `tasar list-changes` | Показать активные изменения. |
| `tasar sync <name>` | Синхронизировать дельта-спеки изменения с главными спеками. |
| `tasar archive <name> [--force]` | Архивировать изменение. |
| `tasar import <path> [--force]` | Импортировать OpenSpec-проект. |

### Команды Tasar

```bash
tasar init                        # инициализация проекта
tasar new <name>                  # создать новое изменение
tasar list-changes                # список активных изменений
tasar sync <name>                 # синхронизировать дельта-спеки → главные спеки
tasar archive <name> [--force]    # архивировать изменение
tasar import <path> [--force]     # импортировать OpenSpec-проект
```

### Типовой сценарий

```bash
# Один раз — подготовить структуру спецификаций
tasar init

# Начать работу над изменением
tasar new add-notifications

# После завершения — синхронизировать и архивировать
tasar sync add-notifications
tasar archive add-notifications
```

`--force` используйте только осознанно: он предназначен для обхода защитных проверок при архивировании или импорте.
